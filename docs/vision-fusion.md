# 视野融合与身体部位暴露

## 保留的视觉形式

继续使用原来的 yaw/pitch 射线网格、眼睛到最近环的光束、地面/墙面/天花板投影，以及半透明加色和绿—黄—红危险色。光束继续近浓远淡；融合后的投影面使用统一危险值决定颜色与透明度，避免原视野的距离灰底在交界处形成色差。显示条件仍为潜行时，敌对生物自动显示，其他生物标记后显示。

融合只作用于投影面；来自不同生物的空中光束保留各自形状。沿用原来的加色混合和深度设置。重叠的同平面投影只填充一次，原来的内部描边消失；外环、孔洞和不相连区域保留。不同楼层不做 XZ 合并。墙地公共边段不重复描边，描边宽度仍为 0.2 格，但展开方向改为所在面的切向。

## 共享的遮挡与警觉计算

`BodyVisibility` 使用目标当前碰撞箱宽度、高度和眼高，分别采样头部、躯干、腿部。每部分有中心和两侧三个点，每个点独立进行 FOV 与物理遮挡判断；继续遵守 `SEE_THROUGHS` 方块标签。

`BodyExposure` 保存每部分的可见比例，以及隐藏、低、中、高、完全暴露等级。综合比例为：

```
exposure = head × 0.30 + torso × 0.50 + legs × 0.20
```

实际 `hasLineOfSight` 使用同一份结果判断是否有身体部位可见，`StealthEngine` 使用综合比例修正涨条速率。例如只露出整个头部时，速率为全身可见时的 30%。接触目标的原有检测例外保留，接触时不享受局部遮挡的速率减免。

这份暴露比例是观察者相关的数据，不覆盖玩家全局 `VISIBILITY` 属性或 HUD 暴露条。全局光照、姿态、效果等计算继续保留；身体遮挡作为额外乘数。

`DetectionMath` 统一距离、全局暴露度、警戒状态及身体遮挡对涨条速率的影响。危险预测使用当前剩余反应时间和警觉进度；转为 AWARE 的那个 tick 同时执行第一次涨条。所有生物使用同一颜色标尺，危险值为 `120 / (120 + discoveryTicks)`；无法发现为 0。颜色在片元着色器中根据插值后的危险值计算，避免红绿 RGB 直接插值产生暗淡中间色。

危险颜色使用明确的三档：预计发现时间 ≤10 秒（200 tick）为红色，>10 秒且 ≤30 秒（600 tick）为黄色，其余为绿色。10 秒整属于红色，30 秒整属于黄色；无法发现为绿色。着色阈值兼容顶点颜色的 8 位量化，避免临界 tick 被分到错误档位。该调整只改变显示映射，实际警觉速率不变；视野交界的危险场过渡继续保留。投影面的透明度随危险值从 0.20 到 0.36，并受原有 `maxOpacity` 上限约束。

## 投影与新遮挡系统的连接

`ConeRaycaster` 额外保存每个命中点的表面法线。`HeatmapComputer` 直接使用这份原密度投影网格，不再另做 32×12 射线或建立大体积热力图数组。

地面命中点作为假想玩家脚部位置；墙面、天花板命中点作为假想身体中心附近的位置。采用真实玩家当前姿态尺寸和全局暴露度，调用共享身体遮挡判断并计算发现时间，再在原投影网格内插值着色。低暴露度时的最小感知距离例外也参与预测。

范围限制：仍然是对原投影采样的危险着色。原射线未覆盖的地面不会因为头部可以从矮墙后露出而额外生成投影；墙面预测也不是可站立位置预测。没有新增全地面扫描或目标位置光照预测。实际玩家的身体部位检测不受这个投影采样限制。

## 融合与性能

`SurfaceVisionFusion` 按三角形所在三维平面分组，使用玩家附近的局部坐标计算。Java 标准库 `Area` 做平衡树式并集，提取外环和孔洞。GPU 路径用扫描条带对并集覆盖面做无重叠三角化；危险值不参与 CPU 多边形分区。公共描边通过空间索引筛选候选边，再执行原有精确共线与重叠判断。

`VisionFieldScene` 只准备不可变几何快照、空间索引和纹理布局；`GpuVisionField` 在渲染线程生成每格 8 像素的 RG32F 危险图集。纹理缓冲保存原始三角形、并集边界和分块索引；片元计算最高危险值及原有一格宽的保守交界过渡，不增加黄色预警圈。图集线性过滤显式检查边界，阻断跨孔洞和孤岛的颜色插值；不足一个纹素的覆盖面回到解析危险计算。不同平面单独计算，外轮廓、孔洞和光束几何保持原样。

颜色仍使用 ≤10 秒红、>10 且 ≤30 秒黄、其余绿的规则，以及原有 8 位危险值量化、透明度、加色混合与光束距离淡出。危险图集的空间分辨率为 1/8 格，颜色分界允许纹素尺度的采样差异；几何覆盖不被栅格化近似。CPU 的 `fuseForDisplay` 作为容量不足或 GPU 失败时的回退，改为平坦区域保留大三角形、危险变化与颜色分界处细分。`-Dstealthandalert.vision.forceCpu=true` 可手动选择回退路径。

绘制通过 `ShaderProgram.bind()` 和 `VertexBuffer.draw()` 直接执行，保留危险图集的五个专用采样器。不能改回 `drawWithShader()`：Veil 的 `ShaderInstance` 适配器会调用 `bindSamplers()`，把未注册在其纹理缓存中的专用采样器重新指定为缺失纹理，覆盖已设置的绑定。首次启用图集时 DEBUG 日志同时记录预测时间与三色采样数量，便于区分计算输入和绘制问题。

性能机制：

- 实际目标检测按游戏 tick 缓存，位置、朝向、尺寸、视距变化会改变缓存键，避免门卫检查和涨条重复发射射线。
- 投影、身体遮挡、警觉数值分开缓存。仅警觉进度、反应时间或状态系数变化时，复用物理采样，只更新预测时间。
- 投影和身体缓存各有独立的 10 tick 刷新期限；观察者位置、眼位、朝向、视距、玩家姿态及检测范围改变会使对应缓存失效。附近区块的方块变化立即使缓存失效，其他远处方块变化不触发重算；区块载入和配置变化也受刷新期限限制。
- 投影及身体预测在客户端主线程按客户端 tick 执行：锁定或警戒每 tick，移动/转头每 2 tick，静止每 10 tick。每个作业共享观察者 FOV、眼位和尺寸常量，仍完整检测各身体部位的三个点。
- 每 tick 最多完成 4 个生物，预算目标为 3 ms；投影射线、向下回落射线和身体采样点之间均可暂停，下一 tick 优先继续未完成作业。单条射线或单个身体点不能在内部中断，因此预算仍允许少量超出；显示保留上一份完整结果。
- 优先更新最久未更新的生物，避免预算不足时一直饿死远处实体。
- 世界和实体读取不交给后台线程。后台只处理不引用实体/世界的几何快照，最多一个任务在途；变化合并到下一次任务。
- 几何或危险数据没有变化时不重建；只改颜色时复用并集、填充网格、纹理布局与描边缓冲，只刷新危险纹理和必要的光束数据。GPU 顶点缓冲及图集资源复用。
- 过渡查询使用空间索引和共享顶点缓存；按来源最大危险值优先查询，跳过不能提高当前危险值的来源。孔洞检查使用局部边段，避免逐顶点反复遍历整个并集轮廓。
- 世界、玩家、显示状态变化时清理缓存、分段作业与 GPU 资源；旧世界或已移除实体的结果不会安装。资源重载后重新取得 Veil 着色器和重建危险图集，图集生成期间完整恢复 OpenGL 状态。
- 删除了原来的逐帧 INFO 诊断日志。

密集交叠仍会增加后台融合延迟；等待期间绘制上一份网格，不阻塞渲染线程。回归程序输出 12 个交叠视野的融合耗时供比较，该数值不是游戏 FPS 基准。

## 验证

日常更新执行编译与针对性的显卡冒烟：

```powershell
.\gradlew.bat compileJava smokeVision
```

`smokeVision` 创建隐藏的 OpenGL 3.3 窗口，检查实际显卡上的颜色临界值、距离渐变、透明度、重叠取最大、交界连续、窄孔洞过滤、覆盖面积、颜色刷新复用几何、混合采样器校验、Minecraft 的真实顶点格式及 GL 状态恢复。额外通过正式绘制入口和真实 `VertexBuffer` 检查不同平面的红黄绿采样及采样器保留，不调用整套回归。必要时再手动执行 `verifyVision`；`check` 仍包含它。原回归覆盖身体遮挡、多边形并集、楼层、墙地接缝和交叉危险梯度。

如果已有工程构建产物，但 Gradle 插件无法下载，可以执行 `scripts/verify-vision-cached.ps1`。它只验证本次改动源码与回归程序，使用已有主类和依赖缓存，不等价于完整 Gradle 构建。

仍需游戏内确认：潜行切换、标记生物、墙面和台阶光斑、视野转动、多个生物重叠、切换维度、资源重载，以及使用 shader 包时的绘制效果。几何回归不能替代实际渲染检查。
